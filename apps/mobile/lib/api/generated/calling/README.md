# pguard_calling_api (EXPERIMENTAL)
v2 OpenAPI contract for the calling service (source of truth — codegen produces Rust
handler stubs/types, the Dart client, the TS client). WebRTC voice/video SIGNALING; the
media plane is the Node mediasoup SFU (brokered by calling over a service-JWT).

v2 rules baked into the contract:
  1. **Participant-only authz.** A call may only be placed between the two participants of
     an ACTIVE booking — verified via booking's service-JWT'd `/internal/bookings/{id}`.
     The `callee` is DERIVED from the booking (the other participant), never supplied by
     the client (no dialing strangers / IDOR).
  2. **Events (outbox).** State changes emit `pguard.events.calling.{initiated,accepted,
     rejected,ended}` in the SAME tx (transactional outbox); notification consumes them.
  3. **Generic errors.** No enumeration / no internal leak.

## WebSocket signaling — `GET /ws/call`
- **Auth = `Authorization: Bearer <access-token>` on the upgrade request.** A token in the
  URL query is NEVER read → such a request is rejected `401` (no sensitive data in the WS
  URL). This is not expressible in OpenAPI paths, so it is documented here.
- After open, the client sends JSON frames:
  `{ \"type\": \"signal\", \"call_id\": \"<uuid>\", \"signal\": <opaque SDP/ICE> }`.
  The server looks up the call's two participants, verifies the sender is one of them, and
  forwards `{ \"type\": \"signal\", \"from\": \"<uuid>\", \"call_id\": \"<uuid>\", \"signal\": ... }` to
  the OTHER participant's live socket. Errors come back as
  `{ \"type\": \"error\", \"message\": \"<reason>\" }`. A non-participant / unknown call is refused.

Client-facing paths are served behind the gateway under `/v1`. Success responses use the
standard `{ success, data }` envelope; errors use `ErrorBody`.
