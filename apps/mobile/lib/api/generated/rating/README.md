# pguard_rating_api (EXPERIMENTAL)
v2 OpenAPI contract for the rating service (source of truth — codegen produces Rust
handler stubs/types, the Dart client, the TS client). Split from the v1
`../guard-dispatch/services/booking` god-service.

v2 rules baked into the contract:
  1. **Authoritative authz.** A review is verified against booking's service-JWT'd internal
     read (`GET /internal/bookings/{id}`): the caller must be the booking's customer and the
     booking must be `completed`. The reviewed `guard_id` comes from the booking, never the
     request body.
  2. **One review per assignment.** DB `UNIQUE(assignment_id)`; a duplicate submit → 409.
  3. **Event on submit.** `pguard.events.rating.submitted` is emitted in the SAME tx as the
     INSERT (transactional outbox); notification consumes it (see `contracts/asyncapi`).
  4. **Public discovery filters `is_visible = true`.** Admin-hidden reviews never surface on
     `GET /guards/{id}/ratings`; admin moderation toggles visibility.
  5. **Generic errors.** No enumeration / no internal leak.

Ratings are whole-star integers `1..=5`; `overall_rating` is required, category ratings
optional. Client-facing paths are served behind the gateway under `/v1`. Success responses
use the standard `{ success, data }` envelope; errors use `ErrorBody`.
